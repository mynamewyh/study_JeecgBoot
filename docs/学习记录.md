## 2026-10-30 · 用 IDEA 终端启动后端

### 想搞清楚什么
在 IntelliJ IDEA 里，怎么不用点绿三角、纯靠终端把后端跑起来。

### 结论
入口只有 `jeecg-system-start` 模块，用 Maven 的 `spring-boot:run` 在 `jeecg-boot` 目录执行，**必须用 `-pl` 指定模块，且不要加 `-am`**。实测启动耗时 **10.8 秒**。

### 命令

```powershell
# IDEA 终端快捷键 Alt + F12（默认 PowerShell）
cd E:\Java\JeecgBoot\jeecg-boot
mvn -pl jeecg-module-system/jeecg-system-start spring-boot:run
```

停止：终端里按 `Ctrl + C`。

### 验证方式

日志出现这两行即成功：

```
Started JeecgSystemApplication in 10.837 seconds
Application Jeecg-Boot is running!
	Local: http://localhost:8080/jeecg-boot
```

再访问接口文档确认端口通：`http://localhost:8080/jeecg-boot/doc.html` → 200。

### 关键点（为什么这么写）

| 点 | 说明 |
| --- | --- |
| 工作目录 | 必须是 `E:\Java\JeecgBoot\jeecg-boot`，Maven 根 `pom.xml` 在这里；外层 `E:\Java\JeecgBoot` 是仓库根，没有后端 pom |
| `-pl` | 只有 `jeecg-system-start` 有 `JeecgSystemApplication` 主类；不加 `-pl` 会让所有模块都执行 run 目标而报错 |
| 不加 `-am` | `-am` 会把 `spring-boot:run` 连带跑到依赖模块上；能不加是因为各模块 jar 已 `install` 到本地仓库 `E:\Java\maven-repo` |
| 改了底层模块 | 改 `jeecg-boot-base-core`、`jeecg-system-biz` 等之后必须先 `mvn -pl <模块> -am clean install -DskipTests`，否则 `run` 用的还是旧 jar |
| profile | 不用写 `-P dev`：根 `pom.xml` 里 `dev` 是 `activeByDefault`，`application.yml` 的 `@profile.name@` 会被资源过滤替换成 `dev` |
| 改 yml 后 | 直接重跑命令即可生效，`spring-boot:run` 会先执行 `test-compile` 重新过滤资源，不用 install、不用打包 |

### 踩坑

1. **终端报 `mvn 不是内部或外部命令`** —— IDEA 终端没继承新配的环境变量。关掉 IDEA 重开，或用全路径：
   `& E:\Java\tools\apache-maven-3.9.9\bin\mvn.cmd -pl jeecg-module-system/jeecg-system-start spring-boot:run`
2. **日志中文全是乱码**（`��Ʒ������`）—— Jeecg 控制台按 GBK 输出、终端是 UTF-8 导致的显示问题，**不影响运行**。想看正常中文：终端先 `chcp 936`，或 Settings → Editor → File Encodings 三个都设 UTF-8。
3. **`Port 8080 was already in use`** —— 先找占用：
   ```powershell
   netstat -ano | findstr :8080
   taskkill /PID <查到的PID> /F
   ```
4. **绿三角启动报 `@profile.name@` 解析不了** —— 那是 IDEA 自己编译、不走 Maven 资源过滤。学习阶段统一用终端命令，行为最确定，日志也全在眼前。

### 备选启动方式

```powershell
# 1) 跑已打好的 fat jar（target 里 382MB 那个，省 Maven 启动开销）
java -jar E:\Java\JeecgBoot\jeecg-boot\jeecg-module-system\jeecg-system-start\target\jeecg-system-start-3.9.5.jar

# 2) 用现成脚本（内部是同一条 mvn 命令，已设好 JAVA_HOME/PATH）
& E:\Java\scripts\start-backend.bat

# 3) 换端口 / 指定 profile / 限制内存
mvn -pl jeecg-module-system/jeecg-system-start spring-boot:run -Dspring-boot.run.arguments=--server.port=8081
mvn -pl jeecg-module-system/jeecg-system-start spring-boot:run -Dspring-boot.run.profiles=prod
mvn -pl jeecg-module-system/jeecg-system-start spring-boot:run "-Dspring-boot.run.jvmArguments=-Xmx1g -Xms512m"
```

## 2026-10-30 · 代码托管到 GitHub

### 结论
项目已推送到公开仓库：**https://github.com/mynamewyh/study_JeecgBoot**

- 定位：**学习副本**（不是 fork），历史从快照开始，基线提交 `a0712e4`（jeecgboot/JeecgBoot 3.9.5）。
- 为什么用快照：本地是 `depth=1` 浅克隆，浅历史推送会被 GitHub 拒绝
  （`! [remote rejected] main -> main (shallow update not allowed)`）；
  拉全量历史要多下载 + 上传约 100 MB，对学习副本没有价值。
- 现状：`origin` 指向自己的仓库，`main` 已跟踪 `origin/main`（首次推送 commit `58d1e85`，4051 个文件）。

### 踩坑

- `jeecg-boot/config/`（启动时从 jar 拷到本地的代码生成模板）、`jeecgboot-vue3/.env.development.bak`
  已加入 `.gitignore`，不要入库。
- 想对照上游更新：`git remote add upstream https://github.com/jeecgboot/JeecgBoot.git`

  否则浅历史被带回本地，push 会再次被拒。
- 单个文件超过 100 MB 会被 GitHub 直接拒收（本项目 `target/*.jar` 已在忽略列表里）。
