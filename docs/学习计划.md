### 1.3 三条贯穿全程的原则（手册附录，贴显示器上）

1. **别找框架源码全貌** —— 你只需要吃透 `base-core` 的 6 个类和 `demo` 模块的 5 个文件，其余是 Spring Boot 拼装 + 外部 jar。

## 二、分阶段详解

### 阶段 0：Java / Spring Boot 最小补课（4–6h，1–2 天）

> 目标不是成为 Java 工程师，而是达到**「能看懂 demo 每一行、能改、能写同款」**。凡是用不到的一律跳过。

#### 0.1 学习目标

- 看懂手册 §4.2 的后端六件套代码的**每一行**（类、注解、泛型、继承）；
- 理解 Spring 的 IoC/DI：**要什么声明什么，不要 new**；
- 会用 Maven 的日常命令和 `-pl` / `-am`，知道本地仓库在哪。

#### 0.2 关键内容（Laravel → Java 对照）

| Laravel / PHP | Java / Spring | 注意点 |
| --- | --- | --- |
| `$var` 啥都装 | 强类型：`String name`、`BigDecimal amount` | 编译期就报错，这是好事（手册 §1） |
| `array` | `List<X>`、`Map<String,Object>` | 泛型 `<X>` 是类型参数 |
| class + trait | class + interface；单继承多实现 | `Controller extends JeecgController`；`ServiceImpl<M, T> implements IService` |
| 魔术方法 / 手写 getter | Lombok `@Data` 编译期生成 | IDEA 必须开注解处理（见易错点） |
| `composer.json` / vendor | `pom.xml` / `E:\Java\maven-repo` | 多模块父子 pom；改底层模块记得 `-pl ... -am` |
| 全局函数随手调 | 依赖注入 `@Autowired` / 构造注入 | **不要 new** Service/Controller |
| 无编译步骤 | `mvn compile` 编译期检查 | 改完方法体可热替换，改字段/注解必须重启（手册 §0.3） |

**Java 语法最小集**（对照廖雪峰教程看，见资源清单）：

1. 基本类型与包装类型（`int`/`Integer`、`long`/`Long`）；`String` 比较用 `equals` 不用 `==`；
2. `List` / `Map` 的构造与遍历（含 lambda、`Arrays.asList`）；
3. 类 / 接口 / 继承 / 实现 / 泛型 —— 重点读懂这行：
   `public class DemoCustomerServiceImpl extends ServiceImpl<DemoCustomerMapper, DemoCustomer> implements IDemoCustomerService`
4. 注解是什么：编译期元数据（`@Data`、`@Override`）vs 运行期反射（`@Autowired`、`@RequestMapping`）；
5. Lombok 四个：`@Data`、`@Slf4j`、`@Accessors(chain = true)`、`@EqualsAndHashCode(callSuper = false)`；
6. `Date` 与 `BigDecimal`（**金额永远用 BigDecimal，不用 float/double**）；
7. Stream 会用 `filter` / `map` / `collect` 即可（`SysUserServiceImpl` 里常见）；
8. 异常体系与 `try/catch`（Java 的 checked exception 和 PHP 不一样，但业务代码里大多直接 `RuntimeException`）。

**Spring Boot 最小集**：

- IoC 容器与注解：`@Service` / `@Component` / `@RestController` / `@Mapper` / `@Autowired`；
- MVC 注解：`@GetMapping/@PostMapping/@PutMapping/@DeleteMapping` + `@RequestBody` / `@RequestParam` / `@PathVariable`；
- 配置：`application.yml` + profile（`@profile.name@` 由 Maven 过滤替换，见手册 §1 与本机 `pom.xml`）；
- Maven：生命周期 `clean → compile → package → install`、坐标 `groupId:artifactId:version`、`-pl`（只构建某模块）/ `-am`（连依赖一起）、本地仓库与镜像（`settings.xml`）。

#### 0.3 实践任务

1. 读廖雪峰 Java 教程的「快速入门 / 面向对象 / 集合 / 注解」四块，每学一节在 IDEA 里建一个 `Main` 类亲手跑一遍；
2. **核心产出**：把手册 §4.2 的 `DemoCustomer`（Entity）和 `DemoCustomerController` 整段抄到自己的类里，给**每个注解、每个类型、每个关键字写中文注释**，写不出就查，写到能脱口而出为止；
3. 用 `Main` 写一段：构造 `List<Map<String, Object>>`、遍历、过滤，感受强类型和泛型；
4. IDEA 环境体检（做完截图存学习记录）：Project SDK = JDK 17；Maven settings 指向 `C:\Users\Administrator\.m2\settings.xml`；Lombok 插件已装、Annotation Processors 已开（Settings → Build → Compiler → Annotation Processors → Enable annotation processing）；
5. 通读 `E:\Java\JeecgBoot\jeecg-boot\pom.xml` 的 profiles 段（`<profile.name>` 和 `activeByDefault`），和 `application.yml` 对照看。

#### 0.4 重点与易错点

| 易错点 | 说明 |
| --- | --- |
| ⚠️ Lombok 报「找不到 getter」 | IDEA 没开注解处理，见任务 4（手册 §6 症状表同款） |
| ⚠️ `==` 比较字符串 | Java 里比内容必须 `.equals()`，这个坑每个 PHP 转 Java 的人都踩 |
| ⚠️ 抄老教程编译不过（`javax.servlet`） | 本项目是 **jakarta** 命名空间，全部 `jakarta.*`（手册 §6） |
| ⚠️ 抄 demo 时把 `fastjson` 也抄了 | 老代码用 fastjson 1.x，**新代码用 `com.alibaba.fastjson2`**（手册 §4.2 提示） |
| ⚠️ 想「new 一个 Service」 | Spring 里全走注入，直接 new 出来的 Bean 里没有依赖、没有代理 |
| ⚠️ 想一次性看完 Java 全部语法 | 没有必要。按最小集来，缺什么查什么 |

#### 0.5 自检（过线标准）

- [ ] 不看手册能说出 `@Data` 帮你生成了哪 4 个方法；
- [ ] 能解释 `ServiceImpl<DemoCustomerMapper, DemoCustomer>` 两个泛型各是什么、为什么这么写；
- [ ] 能说出 `mvn clean install` 和 `mvn -pl jeecg-boot-base-core -am` 各自干了什么；
- [ ] 能说出金额字段为什么用 `BigDecimal`、主键为什么是 `String`（手册 §1 铁律 4）。

### 阶段 1：环境跑通 + 心智模型转换（3–4h，1 天）

> 对应手册 §0–2，即原七日计划的 D1。你的第一个里程碑：**L0**。

#### 1.1 学习目标

- 一键起全套，能说出每个服务的端口和职责；
- 把手册 §1 的「PHP → Jeecg 映射表 + 五条铁律」变成自己的东西；
- 建立「看日志、抓请求、查 SQL」的排查基本功。

#### 1.2 关键内容（手册映射）

- §0.3：**三个必须知道的事实**——精简版仓库没有 Online 后端；前端菜单/路由来自数据库 `sys_permission`（component 字符串映射 `src/views/**`）；Java 没有「改完刷新就生效」；
- §1：心智模型映射表 + 五条铁律（Controller 只做转发、一表五文件、时间字段 Date、主键 String+ASSIGN_ID、接口返回 `Result<T>`）；
- §2.1：启动方式（`start-all.bat` 一键 / `start-backend.bat` + `pnpm dev` 分开 / IDEA 直跑 `JeecgSystemApplication`）；
- §2.2：三件基本功——**开 SQL 日志**（`application-dev.yml:175`）、DevTools 抓登录、doc.html 直接调接口；
- §2.3：日志文件在哪（`LOG_HOME = ../logs` 是**相对启动工作目录**，bat 跑和 IDEA 跑位置不一样）。

#### 1.3 实践任务

1. 用 `E:\Java\scripts\start-all.bat`（或 start-backend + start-frontend 分开）起全套，后端日志出现 `Application Jeecg-Boot is running!` 才算成功；
2. 打开 SQL 日志开关（`application-dev.yml:175` 取消 `#log-impl` 注释）→ **重启后端**；
3. 浏览器 DevTools 登录一次，抓 `POST /jeecgboot/sys/login`：看请求体（`username/password/captcha/checkKey`）、响应体（`code:200 + result.token`）、token 落在 `localStorage`；
4. 打开 `http://localhost:8080/jeecg-boot/doc.html`，把 `/sys/login`、`/test/jeecgDemo/list` 各在线调一次；
5. 去日志目录把当天的 `jeecgboot-yyyy-MM-dd.0.log` 和 `error-log.html` 打开看一眼，学会用 `Ctrl+F` 搜接口名；
6. **手抄**手册 §1 的映射表和五条铁律到 [学习记录.md](学习记录.md)（手抄一遍的记忆远超看三遍）。

#### 1.4 重点与易错点

- ⚠️ 日志中文乱码（`��Ʒ`）：GBK 输出 vs UTF-8 终端，**不影响运行**，看 SQL 行号即可；想正常显示就 `chcp 936`；
- ⚠️ 8080 被占：`netstat -ano | findstr :8080` → `taskkill /PID xxx /F`；
- ⚠️ 前端 3100 常常已经在跑，别重复起；
- ⚠️ SQL 日志是**你以后 80% 排查的起点**，本阶段必须开好。

#### 1.5 自检

- [ ] 能指着控制台里的一条 SQL 说出「这是我刚才点的哪个按钮触发的」；
- [ ] 能说出登录 token 存在前端哪里、校验时放哪个请求头（`X-Access-Token`）；
- [ ] 能说清 IDEA 直跑和 start-backend.bat 跑，日志文件分别在哪（手册 §2.3）。

### 阶段 2：读通一条完整链路（3–4h，1 天）

> 对应手册 §3，原 D2。**最关键的一天**，链路上去了后面全是坦途。

#### 2.1 学习目标

- 白纸画出「列表查询」从前端点击到 SQL 再到渲染的完整链路；
- 理解四个框架魔法：`QueryGenerator.initQueryWrapper`、`JeecgController` 基类、`Result<T>`、`@AutoLog` / `@PermissionData`。

#### 2.2 关键内容

- §3.0：demo 单表是官方留下的**标准答案**，前后端 8 个文件（表格里列出了全部路径）；
- §3.1：链路图（`useListPage` → `defHttp.get` → Vite 代理 `/jeecgboot` → `JwtFilter` → `Controller.list` → `QueryGenerator` → `service.page` → Mapper/XML → MySQL → `Result.OK(IPage)` → axios 拦截器 → `BasicTable`）——**背下来**；
- 四个魔法各自解决的问题：URL 参数自动拼 where（`name=abc`、`age_begin/age_end`、`createTime_ge` 这类后缀语法）；基类白送 Excel 导入导出；统一返回包装（前端只认 `code === 200`）；方法级操作日志 + 数据权限。

#### 2.3 实践任务

1. 打开 §3.0 表格里的 8 个文件逐个精读，controller 和 `index.vue` 两处各读两遍；
2. 手绘链路图（纸笔或 draw.io 都行），**贴显示器上**（手册附录第 3 条）；
3. 在 doc.html 里给 `/test/jeecgDemo/list` 传 `name=xxx` 和 `age_begin=18&age_end=30` 这类参数，对照 SQL 日志看 where 子句变化；
4. 进 `JeecgController` 基类源码，数一数它白送了哪些方法（`exportXls` / `importExcel`…）；
5. 在 demo 代码里找到 `@AutoLog`、`@PermissionData`、`Result.OK` 的三处实际使用位置；
6. 用 DevTools 完整抓一次列表请求：看 Request URL、`X-Access-Token` 头、响应 JSON 结构（`result.records / total`）。

#### 2.4 重点与易错点

- ⚠️ 分页参数 `pageNo/pageSize` 是**请求参数**带过去的，`total` 来自 `IPage`，不是前端算的；
- ⚠️ 看到 Network 里是 `localhost:3100/jeecgboot/...` 是 Vite 代理，**不是跨域问题**（手册 §5.2）；
- ⚠️ `QueryGenerator` 的参数后缀语法（`_begin/_end/_ge` 等）是 Jeecg 约定，和你过去的 Laravel 查询构造器思路类似但写法不同，值得单独记一页笔记。

### 阶段 3：第一个 CRUD 模块（7–8h，2 天）

> 对应手册 §4，原 D3–D4。产出物：`demo_customer` 客户表的完整前后端。这是**「能干活」的门槛**。

#### 3.1 学习目标

- 独立走完「建表 → 后端六件套 → 前端三件套 → 挂菜单 → 授权 → 联调」全流程；
- 理解菜单/路由来自数据库的机制（`sys_permission.component` → `src/views/**`）；
- 会用两种免登录方案（`@IgnoreAuth` / `excludeUrls`）。

#### 3.2 关键内容（手册映射）

- §4.1：建表 SQL + 两个纪律——字段 `snake_case` 自动映射 Java `camelCase`（`application-dev.yml:172`）；**不要改** `jeecgboot-mysql-5.7.sql` 初始化脚本；
- §4.2：后端六件套（Entity / Mapper / IService / ServiceImpl / Controller + Mapper.xml 备用）——照 `JeecgDemoController` 抄，**import 换 fastjson2**；
- §4.3：前端三件套（`customer.api.ts` / `customer.data.ts` / `index.vue` + 弹窗 `CustomerModal.vue` 抄 demo）；
- §4.4：**挂菜单是关键一步**——组件路径规则（相对 `src/views/`、不带 `.vue`、不带开头 `/`）、角色授权、退出重登；附等价 INSERT SQL；
- §4.5：免登录两种方式二选一（`@IgnoreAuth` 注解 或 `application-dev.yml:293` 白名单，白名单改完重启）；
- §4.6：验收清单。

#### 3.3 实践任务

1. 用 §4.1 的 SQL 建 `demo_customer` 表（`mysql.exe -uroot -proot jeecg-boot` 直连执行）；
2. 新建包 `org.jeecg.modules.demo.customer`，手写后端六件套（Entity 上注意 `@Excel(name=...)` 是导出表头）；
3. `doc.html` 里调通 `/demo/customer/list|add|edit|delete|queryById` 五个接口；
4. 手写前端三件套 + 弹窗，`pnpm dev` 热更新验证；
5. 走「菜单管理 → 新增 → 角色授权 → 退出重登」把页面挂上去（或执行等价 SQL，字段已核对）；
6. 完成导出 Excel 的两个转发方法（基类已有 `exportXls`）；
7. 给一个接口加上免登录（两种方式各试一次，试完二选一保留）。

#### 3.4 重点与易错点

| 易错点 | 处理 |
| --- | --- |
| ⚠️ 页面白屏 / `Cannot read ... undefined` | 99% 是 `component` 写错或与 `src/views` 路径不匹配（手册 §6） |
| ⚠️ 菜单不显示 | 没授权、`del_flag`、没退出重登——授权后**必须重登** |
| ⚠️ 新增报 `Field 'id' doesn't have a default value` | 主键没加 `@TableId(type = IdType.ASSIGN_ID)`（雪花 ID） |
| ⚠️ 接口 404 | context-path `/jeecg-boot` 漏了、路径拼错、包不在 `org.jeecg.modules.**` 扫描范围 |
| ⚠️ 抄到 `com.alibaba.fastjson` | 换 `com.alibaba.fastjson2`（手册 §4.2 专门提示） |
| ⚠️ 后端没重启 | 新增类/注解不会热加载，必须重启（手册 §0.3 事实 3） |

### 阶段 4：调试四件套（3–4h，1 天）

> 对应手册 §5，原 D5。从「能写」到「能查」。

#### 4.1 学习目标

- 后端：断点全家桶 + 热替换 + 远程调试，每种手法都用一遍；
- 前端：Vite 源码断点 + Vue Devtools + 看懂被 `defHttp` 吞掉的错误；
- 数据层：Druid 慢 SQL、SQL 日志、redis-cli 看登录态。

#### 4.2 关键内容（手册映射）

- §5.1：行断点 / **条件断点**（高频接口必备）/ 异常断点 / `Alt+F8` 求值 / 调用栈 / 字段观察点 / `Ctrl+F9` 热替换（只对方法体）；远程调试 `-agentlib:jdwp=...,address=*:5005`；
- §5.2：Vite 代理原理、Sources 源码断点、看 `X-Access-Token` 与 `code/success/message`、Vue Devtools 看 Pinia（`app-user`/`app-permission`）、**错误被 `defHttp` 拦截器吃掉时在 `src/utils/http/axios/index.ts` 临时加 `console.log`**；
- §5.3：Druid 监控（`/jeecg-boot/druid`，admin/123456）看慢 SQL 和连接池；`@PermissionData` 会让「明明有数据却查不到」，排查时**先注释掉对比一次**；
- §5.4：redis-cli：`keys *token*` 看登录态、`keys *sys:cache:*` 看字典缓存；「登录后立刻掉线/401」十有八九是 Redis 没起。

#### 4.3 实践任务

1. 在 `DemoCustomerController.list` 上打行断点 → 前端点列表 → 断点停下后用 `Alt+F8` 求值查看 `queryWrapper` 的 SQL 段；
2. 打一个条件断点（如 `"admin".equals(q.getName())`）验证只停符合条件的请求；
3. 改 `list` 的方法体（如 orderBy 换字段），`Ctrl+F9` 热替换，不重启验证生效；
4. 用 `java -jar` + `jdwp` 起一次后端，IDEA 配 Remote JVM Debug 连 5005，体验一遍后切回正常启动方式；
5. 安装 Vue Devtools，打开 demo 列表页看 `app-permission` 里的路由和权限数据；
6. 打开 Druid 看一次 SQL 统计；把 `@PermissionData` 注释/还原各一次，对照 SQL 日志的 where 差异；
7. redis-cli 里 `keys *token*` 找到自己的登录 token，删掉后刷新前端看 401 现象（顺手把现象记下来，阶段 5 会用到）。

#### 4.4 重点与易错点

- ⚠️ `Ctrl+F9` 热替换**只对方法体**，改字段/注解/新增类必须重启；
- ⚠️ 接口报错但控制台一片安静：先查 `defHttp` 的 `errorMessageMode: 'message'`（弹 toast 不抛错），临时加 `console.log(response)` 看原始响应；
- ⚠️ 断点停不进去：确认是用 Debug 模式起的后端，不是普通 Run。

#### 4.5 自检

- [ ] 断点停在 `edit` 方法上，并在求值窗口看到拼接出的 SQL；
- [ ] 能说出「接口报错但控制台没报错」时的排查路径；

### 阶段 5：排障训练（3–4h，1 天）

> 对应手册 §6，原 D6。目标不是背表，是**3 分钟定位**的肌肉记忆。

#### 5.1 学习目标

- 把手册 §6 的 17 行症状表变成自己的排查反射；
- 建立「先看日志/网络，再猜代码」的顺序习惯。

#### 5.2 关键内容

手册 §6 症状表分组记忆：

| 症状群 | 关键词 | 手册定位手法 |
| --- | --- | --- |
| 登录类 | 500 / 一直转圈 / 一直跳登录 | 后端第一条异常、`netstat` 查 8080、Redis `keys *` |
| 鉴权类 | 401（没带 token/过期） vs 403（没权限） | DevTools 看 `X-Access-Token`；角色授权 + 重登 |
| 页面类 | 白屏 / 菜单不显示 | 后端返回的 `component` 对照 `src/views`；`sys_permission` 查行 |
| 接口类 | 404（context-path/路径/扫描） / 500（`Invalid bound statement`、`Unknown column`、id 无默认值） | doc.html 搜接口；SQL 日志看真实列名；实体 `@TableId` |
| 数据类 | 分页 total=0 / 明明有数据查不到 | 返回类型 `IPage`；`@PermissionData` 注释对比 |
| 环境类 | 时间差 8 小时 / 乱码 / Flyway validate failed / 上传 413 / 端口占用 | 已有配置别乱改 URL；flyway repair 或临时关（仅本地） |

#### 5.3 实践任务

1. **故意制造 5 个故障，逐个限时 3 分钟定位**（做完还原）：
   - 去 token → 造 401；
   - 角色里取消授权 → 造 403；
   - 把 `sys_permission` 里 component 改错 → 造白屏；
   - 删掉/改错 Mapper XML → 造 500 `Invalid bound statement`；
   - 拼错一个接口路径 → 造 404；
2. 把每个故障的「现象 → 定位过程 → 根因 → 处理」按模板写进 [学习记录.md](学习记录.md)；
3. 通读 §6 全表，给每一行标注「我的定位第一动作是什么」（比如 500 先看后端日志第一条）。

#### 5.4 重点与易错点

- ⚠️ 401 和 403 不是一回事：401 = 认证没过（没 token/过期），403 = 认了但没权限；
- ⚠️ 500 时**先看后端日志第一条异常**，别去前端猜；
- ⚠️ Flyway 报 validate failed：说明手工改过库，开发库可 `flyway repair`，**临时 `enabled: false` 只在本地用**。

#### 5.5 自检

- [ ] 随机抽 §6 表里 3 行症状，能在 3 分钟内定位到根因（找人出题或自己遮住表测）；
- [ ] 学习记录里至少有 3 条「现象 → 根因 → 处理」的排障记录。

### 阶段 6：代码生成器 + 业务规则（5–6h，1–1.5 天）

> 对应手册 §7 + §8 的 D7 任务。产出：会用生成器提效、会用数据权限/Flyway 做真实规则。

#### 6.2 关键内容（手册映射）

- §7：Web 端「Online 表单开发 → 代码生成」**本仓库后端缺失，不可用**；GUI 生成器两个入口 + 「生成物是模板代码，仍需人工改」的定位；

#### 6.3 实践任务

1. 跑一次 `JeecgOneGUI`（Swing 窗口，连库选表生成），把生成的代码和阶段 3 手写的对比，找出「生成器帮你写了什么、没写什么」；
2. 跑一次 `JeecgOneToMainUtil`（改 main 里的表名/实体名/包名）体验一对多生成；

4. 给 `demo_customer` 写一个自定义查询接口（如「按金额区间统计」，用 XML 手写 SQL，体验一次 `namespace` 全限定名）；

#### 6.4 重点与易错点

- ⚠️ XML 的 `namespace` 必须是 Mapper 全限定名、方法名一致，否则 `Invalid bound statement`（阶段 5 已踩过，这里再温习）；

- ⚠️ `@PermissionData` 的过滤是「查不到」类问题的头号嫌疑，永远先注释对比。

## 五、给「零 Java 基础」的特别提醒（贯穿全程）

1. **编译期报错是礼物**：PHP 是跑起来才炸，Java 是编译期就告诉你。看到红波浪线先读 IDE 的提示，别慌。
2. **前两周会一直想「这要在 PHP 里一行就完了」**——正常。JeecgBoot 的六件套是结构化的代价，换来的是规范、IDE 提示和团队协作，阶段 3 做完你会有切身体感。
3. **每天收尾的 10 分钟记录比当天多学 1 小时更重要**：2–4h/天 的节奏下，遗忘是最大的敌人，[学习记录.md](学习记录.md) 就是你的外置记忆。
4. **卡住超过 30 分钟就走手册 §6 症状表**：先按表定位，定位不动再问人/问 AI，带着「现象 + 日志 + 已试过什么」来问，效率翻倍。
